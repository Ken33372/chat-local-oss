# 上下文注入：一次请求里放了什么

这份文档说明自建后端在发请求前，会往模型上下文里补哪些内容、放在哪里、开关是什么，以及哪些还只是计划。云端模式（前端直连 DeepSeek）不经过本机后端，下面所有注入都不生效。

## 两个位置

| 位置 | 放什么 | 为什么 |
|---|---|---|
| system 前缀 | 内置规则、日期提醒、压缩摘要、联网工具说明 | 同一会话内基本不变，能复用引擎的前缀缓存 |
| 最后一条用户消息里（尾部） | 长期记忆、确认回执 | 每轮随问题变；放尾部只作废最后这一轮，system 和之前的对话缓存都还在 |

记忆块在发送时拼到最后一条用户消息开头，前面加一行「【系统自动附加，不是用户说的话】」。库里存的原话不变，界面上也看不到这段，只影响这一轮发给模型的请求。

为什么不放 system：前缀缓存只认从头开始一模一样的部分。记忆块放进 system，只要选的条目一变，它后面的摘要、规则、整段历史都要重新算一遍；长对话每轮会多等很久。

## system 里现在拼进去的内容

顺序固定：

1. 内置身份句（`DEFAULT_SYSTEM`）
2. 当前日期等提示（`当前信息：…`）
3. 提示词（角色卡，选了才拼）
4. 较早对话的压缩摘要（做过压缩时）
5. 联网工具说明（开启搜索时，含引用编号规则）
6. 固定规则：回答与用户同语言；附件识别失败要如实说

## 提示词（角色卡）

设置 → 提示词。三种状态二选一：不使用 / 使用某一张角色卡。没有单独的「临时文本」输入框——想临时改，就新建一张卡。

- 每张卡：名称（≤40 字）、说明（≤200 字，可选）、正文（≤8000 字）；最多 30 张，名称不能重复
- 全局只生效一张，对所有会话都一样；换了卡或改了正文，下一轮请求立即生效
- 正文只追加在内置身份和日期之后、摘要与联网规则之前，**不能覆盖内置规则**
- 存在 `data/prompts.json`；不进 `config.json`，向导保存不会覆盖
- 云端模式不经过本机后端，设置页只显示提示语

前缀缓存：卡是全局固定文本，同一会话内不变；只在换卡或改正文时使前缀失效一次。

## 尾部拼进去的内容

长期记忆段（启用记忆且未关闭注入时）：

```

```
【系统自动附加，不是用户说的话】
以下是我对用户的长期记忆，可能过时，与本轮无关就忽略：
- 回答尽量用中文
- 下周要交开题报告
```

如果用户在设置里确认或忽略了模型之前提议的记忆，下一轮会在同一段里附一次回执：

```
用户在设置里处理了你之前提议的记忆：
- 已确认：……（已存入长期记忆）
- 已忽略：……（不要再重复提交这一条）
```

修改提案的回执写成「已确认修改：「旧」改为「新」」或「已忽略修改：「旧」保持不变」。

回执按会话只发一次，发送后标记为已通知。

## 长期记忆

### 开关（设置 → 记忆，默认关）

| 项 | 取值 | 默认 |
|---|---|---|
| 启用长期记忆 | 开 / 关 | 关 |
| 注入方式 | 置顶 + 最近 / 按相关性（本地关键词）/ 高级检索（向量，可选重排）/ 不注入 | 置顶 + 最近 |
| 记忆检索方式 | 关键词 / 按相关性（本地打分）/ 高级检索（向量，可选重排） | 按相关性（本地打分） |
| 注入条数 | 1–10 | 5 |
| 允许模型查询与提议 | 开 / 关 | 开 |
| 写入方式 | 提议待确认 / 禁止模型写入 | 提议待确认 |

对应的环境变量：`CHAT_LOCAL_MEMORY`、`CHAT_LOCAL_MEMORY_INJECT_MODE`、`CHAT_LOCAL_MEMORY_SEARCH_MODE`、`CHAT_LOCAL_MEMORY_COUNT`、`CHAT_LOCAL_MEMORY_TOOLS`、`CHAT_LOCAL_MEMORY_WRITE`、`CHAT_LOCAL_MEMORY_SIM_THRESHOLD`（向量注入的最低余弦，默认 0.42）（环境变量优先于界面保存的 `data/config.json`）。

### 注入的选条规则

置顶条目始终保留（最多占满名额），其余按所选注入方式挑选：

| 注入方式 | 怎么挑剩余的 | 依赖 |
|---|---|---|
| 置顶 + 最近 | 按更新时间倒序 | 无 |
| 按相关性（本地关键词） | 与本轮用户消息做字词重合打分；说明命中按 2 倍计，正文按 1 倍 | 无 |
| 高级检索（向量） | 说明与正文拼在一起算向量，按余弦相似度排序；配了重排接口再二次排序 | `EMBEDDING_*`；重排可选 |

关键词只保留有字面命中的条目；向量只保留余弦 ≥ 阈值的条目（默认 0.42，可用 `CHAT_LOCAL_MEMORY_SIM_THRESHOLD` 调整）。命中不足就少注入；完全不命中时只留置顶条目，可能一条都没有，不再回退到“最近”硬凑满。存储在本机 `chat.db` 的 `memories` 表。

### 模型的两个工具

| 工具 | 行为 |
|---|---|
| `search_memory(query)` | 只在**本轮未注入**的条目里查，最多回 5 条；排序方式跟随「记忆检索方式」，高级检索同样可加重排 |
| `remember(text, description?, pinned?)` | 不直接入库，生成一条待确认提案；说明可选，工具提示会要求尽量写 5–15 字 |
| `edit_memory(original, text, description?, pinned?)` | 不直接改原条目，生成一条「旧 → 新」修改提案；`original` 要与记忆原文一致（不一致时按相似度找，找不准会要求先 `search_memory`） |

### 向量与重排

- 向量接口：OpenAI 兼容 `/v1/embeddings`，配置项 `EMBEDDING_PROVIDER` / `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY` / `EMBEDDING_MODEL` / `EMBEDDING_DIM`
- **维度必须手填且与模型一致**（如 Qwen3-Embedding-0.6B 为 1024）；模型或维度变化会自动重算全部向量，存 `memory_vectors` 表
- 重排复用 `RERANK_*`，配了才会对向量候选做二次排序，没配就只按余弦相似度
- 调用失败（服务没开、维度不符、超时）自动回退本地打分，并在设置 → 记忆顶部显示上次错误；不会卡住聊天
- 开销：向量模式每轮多一次 embedding 请求（实测约 0.3 秒，同一句话会缓存），配了重排再多一次（实测约 1 秒）

`remember` / `edit_memory` 的服务端拦截（不靠模型自觉）：

- 正文超过 300 字，或说明超过 30 字
- 与已有记忆字面重合 ≥ 80%（修改时排除被改的这一条）
- 同一条记忆已有待确认的修改，不重复提案
- 当天提案已达 20 条（新增与修改共用额度）
- **本轮调用过联网工具**（`web_search` / `read_url` / `find_in_page`）：一律拒绝，防止网页内容污染长期记忆

### 确认与可见性

- 提案在设置 → 记忆的「待确认」里逐条接受或忽略；输入框上方也会出现「有 N 条记忆待确认」
- 修改提案显示为「旧文（删除线）→ 新文」，接受后原地替换，拒绝则原样保留
- 接受后才写入记忆表，并会作为普通记忆参与注入
- 记忆相关的工具调用会在回复的步骤区显示一行：已带入 N 条长期记忆 / 已查询记忆，找到 N 条 / 已提交 1 条记忆，待你确认 / 记忆未写入（原因）
- 记忆库支持导出 txt、导入 txt/JSON；导入时重复、超长、超总量的条目跳过
- 导出 txt 时，每条先写 `- 正文`，有说明就再写一行 `  说明：…`；JSON 条目支持 `description` 字段
- 上限：正文 300 字、说明 30 字，总量 200 条（导入与手动、模型提议共用）

### 手动整理

设置 → 记忆 → 整理。按字面相似度找疑似重复：短句要求 ≥80%，长句 ≥60%，最多列 20 对。选一条保留，另一条删除；置顶状态取并集。只出建议，不自动改。

## 上下文占用与压缩

- 输入框右下角显示估算用量；上限读 `LLM_CONTEXT_LIMIT`（默认 131072），输出上限读 `LLM_MAX_OUTPUT_TOKENS`
- 本地模式在用量约 60% 时出现「压缩」按钮：把较早内容交给模型生成摘要，保留最近 4 条，原始消息不删；之后的请求改用「摘要 + 最近 4 条」
- 压缩目前是手动的；自动压缩尚未实现

## 还没做的部分

下面这些已在讨论中定过方向，但代码里没有：

| 项 | 设想 |
|---|---|
| 单会话覆盖 | 某个会话单独选卡或临时关闭提示词，不影响全局 |
| 角色卡扩展 | 开场白、头像；第一版只有名称/说明/正文 |
| 跨会话摘要卡 | 每个活跃会话一张短摘要，按相关度注入到尾部槽 |
| 摘要的向量召回 | 摘要卡先算向量，按问题召回 2–3 张，仍放尾部槽（记忆本身的向量选条已上线） |
| 记忆整理（进阶） | 清理过期、标记冲突；重复合并已支持（手动） |

## 排查

| 现象 | 先看 |
|---|---|
| 模型不知道记忆 | 记忆总开关是否打开、注入是否为「不注入」、要用的条目是否排在注入条数之外 |
| 模型仍说「等你确认」 | 回执只发给提案所在的原会话，且只发一次；换会话或已发过就看不到 |
| 模型无法写入记忆 | 写入方式是否为「禁止模型写入」、本轮是否读过网页、是否与已有记忆重复 |
| 模型把记忆当成用户说的话 | 正常现象但应被标记压住：最后一条用户消息里应带「系统自动附加，不是用户说的话」；不带说明请求组装有误 |
| 云端模式看不到记忆 | 设计如此：云端直连不经过本机后端 |
| 模型没按人设回答 | 设置 → 提示词里是否选了卡；正文是否只写了风格、没有写「忽略上面的规则」这类无效指令 |
