# 上下文注入：一次请求里放了什么

这份文档说明自建后端在发请求前，会往模型上下文里补哪些内容、放在哪里、开关是什么，以及哪些还只是计划。云端模式（前端直连 DeepSeek）不经过本机后端，下面所有注入都不生效。

## 两个位置

| 位置 | 放什么 | 为什么 |
|---|---|---|
| system 前缀 | 内置规则、长期记忆、压缩摘要、联网工具说明 | 同一会话内基本不变，能复用引擎的前缀缓存 |
| 最近一条用户消息之前（尾部） | 按问题动态召回的内容 | 每轮可能不同；放尾部只重算尾部，不推翻整段历史 |

当前版本只用到了前缀；尾部槽是给后续「按问题召回」预留的，尚未实现。

## 现在实际拼进去的内容

顺序固定，都在 system 里：

1. 内置身份句（`DEFAULT_SYSTEM`）
2. 当前日期等提示（`当前信息：…`）
3. 长期记忆段（启用记忆且未关闭注入时）
4. 较早对话的压缩摘要（做过压缩时）
5. 联网工具说明（开启搜索时，含引用编号规则）
6. 固定规则：回答与用户同语言；附件识别失败要如实说

长期记忆段的格式：

```
以下是我对用户的长期记忆，可能过时，与本轮无关就忽略：
- 回答尽量用中文
- 下周要交开题报告
```

如果用户在设置里确认或忽略了模型之前提议的记忆，下一轮会在记忆段后面附一次回执：

```
用户在设置里处理了你之前提议的记忆：
- 已确认：……（已存入长期记忆）
- 已忽略：……（不要再重复提交这一条）
```

回执按会话只发一次，发送后标记为已通知。

## 长期记忆

### 开关（设置 → 记忆，默认关）

| 项 | 取值 | 默认 |
|---|---|---|
| 启用长期记忆 | 开 / 关 | 关 |
| 注入方式 | 置顶 + 最近 / 按相关性（本地关键词）/ 高级检索（向量，可选重排）/ 不注入 | 置顶 + 最近 |
| 记忆检索方式 | 关键词 / 按相关性（本地打分）/ 高级检索（向量，可选重排） | 按相关性（本地打分） |
| 注入条数 | 1–10 | 5 |
| 允许模型查询与提议 | 开 / 关 | 开 |
| 写入方式 | 提议待确认 / 禁止模型写入 | 提议待确认 |

对应的环境变量：`CHAT_LOCAL_MEMORY`、`CHAT_LOCAL_MEMORY_INJECT_MODE`、`CHAT_LOCAL_MEMORY_SEARCH_MODE`、`CHAT_LOCAL_MEMORY_COUNT`、`CHAT_LOCAL_MEMORY_TOOLS`、`CHAT_LOCAL_MEMORY_WRITE`（环境变量优先于界面保存的 `data/config.json`）。

### 注入的选条规则

置顶条目始终保留（最多占满名额），其余按所选注入方式挑选：

| 注入方式 | 怎么挑剩余的 | 依赖 |
|---|---|---|
| 置顶 + 最近 | 按更新时间倒序 | 无 |
| 按相关性（本地关键词） | 与本轮用户消息做字词重合打分 | 无 |
| 高级检索（向量） | 问题转向量，记忆按余弦相似度排序；配了重排接口再二次排序 | `EMBEDDING_*`；重排可选 |

任一种方式挑不出结果（例如关键词完全不命中）都会回退到最近，不会注入空段。存储在本机 `chat.db` 的 `memories` 表。

### 模型的两个工具

| 工具 | 行为 |
|---|---|
| `search_memory(query)` | 只在**本轮未注入**的条目里查，最多回 5 条；排序方式跟随「记忆检索方式」，高级检索同样可加重排 |
| `remember(text, pinned?)` | 不直接入库，生成一条待确认提案 |

### 向量与重排

- 向量接口：OpenAI 兼容 `/v1/embeddings`，配置项 `EMBEDDING_PROVIDER` / `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY` / `EMBEDDING_MODEL` / `EMBEDDING_DIM`
- **维度必须手填且与模型一致**（如 Qwen3-Embedding-0.6B 为 1024）；模型或维度变化会自动重算全部向量，存 `memory_vectors` 表
- 重排复用 `RERANK_*`，配了才会对向量候选做二次排序，没配就只按余弦相似度
- 调用失败（服务没开、维度不符、超时）自动回退本地打分，并在设置 → 记忆顶部显示上次错误；不会卡住聊天
- 开销：向量模式每轮多一次 embedding 请求（实测约 0.3 秒，同一句话会缓存），配了重排再多一次（实测约 1 秒）

`remember` 的服务端拦截（不靠模型自觉）：

- 单条超过 300 字
- 与已有记忆字面重合 ≥ 80%
- 当天提案已达 20 条
- **本轮调用过联网工具**（`web_search` / `read_url` / `find_in_page`）：一律拒绝，防止网页内容污染长期记忆

### 确认与可见性

- 提案在设置 → 记忆的「待确认」里逐条接受或忽略；输入框上方也会出现「有 N 条记忆待确认」
- 接受后才写入记忆表，并会作为普通记忆参与注入
- 记忆相关的工具调用会在回复的步骤区显示一行：已带入 N 条长期记忆 / 已查询记忆，找到 N 条 / 已提交 1 条记忆，待你确认 / 记忆未写入（原因）
- 记忆库支持导出 txt、导入 txt/JSON；导入时重复、超长、超总量的条目跳过
- 上限：单条 300 字，总量 200 条（导入与手动、模型提议共用）

## 上下文占用与压缩

- 输入框右下角显示估算用量；上限读 `LLM_CONTEXT_LIMIT`（默认 131072），输出上限读 `LLM_MAX_OUTPUT_TOKENS`
- 本地模式在用量约 60% 时出现「压缩」按钮：把较早内容交给模型生成摘要，保留最近 4 条，原始消息不删；之后的请求改用「摘要 + 最近 4 条」
- 压缩目前是手动的；自动压缩尚未实现

## 还没做的部分

下面这些已在讨论中定过方向，但代码里没有：

| 项 | 设想 |
|---|---|
| 自定义 system | 全局默认 + 单会话覆盖，只能追加人格段，不能覆盖内置规则 |
| 角色卡 | 带名字/头像/开场白的命名预设，本质是可复用的 system 预设 |
| 跨会话摘要卡 | 每个活跃会话一张短摘要，按相关度注入到尾部槽 |
| 向量召回 | 记忆/摘要先算向量，按问题召回 2–3 条，仍放尾部槽 |
| 记忆整理 | 合并重复、清理过期、标记冲突，只出待确认建议 |

## 排查

| 现象 | 先看 |
|---|---|
| 模型不知道记忆 | 记忆总开关是否打开、注入是否为「不注入」、要用的条目是否排在注入条数之外 |
| 模型仍说「等你确认」 | 回执只发给提案所在的原会话，且只发一次；换会话或已发过就看不到 |
| 模型无法写入记忆 | 写入方式是否为「禁止模型写入」、本轮是否读过网页、是否与已有记忆重复 |
| 云端模式看不到记忆 | 设计如此：云端直连不经过本机后端 |
